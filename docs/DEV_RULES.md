# DEV_RULES

## General Rules
- do not refactor unrelated files
- do not widen scope beyond the approved phase
- keep repo changes minimal and high-signal
- prefer plain language over vague process jargon
- keep the starter project-agnostic by default

## Collaboration Rules
- read the active phase spec before implementing
- read SEC files before implementing when they exist
- update SEC when a decision changes what another collaborator or agent should do
- do not assume private planning context is shared unless it is exported into the repo

## Verification Rules
- do not claim completion without verification
- keep proof artifacts aligned with milestone claims
- update compactions when major verified state changes
